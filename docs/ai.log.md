# L06 — AI ашигласан тэмдэглэл

## 1. Асуудал

GitHub repository дээр L07-ийн traceability файлын байрлал шаардлагатай хавтастай зөрж байгааг анзаарсан.

## 2. AI-д тавьсан асуулт

GitHub дээр файл харагдахгүй эсвэл шаардлагатай хавтас дотор байхгүй үед ямар шалтгаан байж болох вэ?

Код бичихгүйгээр 3 боломжит шалтгаан болон шалгах аргыг тайлбарла.

## 3. AI-ийн санал болгосон таамаглалууд

### Таамаглал 1
Файл буруу хавтас дотор байж болно.

Шалгах арга:
- Repository-ийн үндсэн хавтас болон `docs/` хавтсыг нээх.
- Файлын бодит замыг шалгах.

### Таамаглал 2
Файлыг commit хийгээгүй байж болно.

Шалгах арга:
- Тухайн branch-ийн commit history шалгах.
- GitHub дээр файл харагдаж байгаа эсэхийг шалгах.

### Таамаглал 3
Өөр branch дээр файл үүсгэсэн байж болно.

Шалгах арга:
- Одоогийн branch-ийг шалгах.
- Main болон feature branch-ийг тус тус шалгах.

## 4. Анхны шалгалт

- Repository-ийн main branch-ийг нээсэн.
- Анхны шалгалтаар traceability файлын байрлалын асуудал илэрсэн.
- Файлын байрлал болон branch-ийн ялгааг тусад нь шалгах шаардлагатай гэж тэмдэглэсэн.

## 5. Засварын дараах бодит шалгалт — 2026-11-23

- Шалгасан repository: `Regun4k/inventory-system`.
- Шалгасан branch: `feature/lab08-g1-review`.
- Засварын дараах бодит зам: `docs/traceability.md`.
- Файл feature branch дээр GitHub-д нээгдэж, 8 User Story болон 24 AC-ийн холбоос агуулж байгааг шалгасан.
- Энэ нь PR-ийн салбар дахь байдал; main branch-д PR нэгтгэгдсэн гэсэн үг биш.

## 6. AI-ийн таамаглалыг үнэлсэн нь

- “Файл огт commit хийгдээгүй” гэсэн таамаглалыг feature branch дээр файл нээгдэж байгаагаар няцаасан.
- “Файл өөр branch дээр байж болно” гэдэг нь branch-ийг тусад нь шалгах шаардлагатайг харуулсан.
- Файлын зөв замыг feature branch дээр `docs/traceability.md` гэж баталгаажуулсан.

## 7. Миний дүгнэлт

AI-ийн санал болгосон боломжит шалтгаан бүрийг GitHub дээр шалгаж байж дүгнэсэн. Branch болон файлын замыг хамтад нь шалгах хэрэгтэйг ойлгосон.

Цаашид AI-ийн зөвлөгөөг бодит орчинд шалгаж байж ашиглана.

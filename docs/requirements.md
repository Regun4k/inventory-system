
# L04 — User Story ба Acceptance Criteria

## US-01 — Бараа бүртгэх

As an агуулахын ажилтан,

I want to шинэ бараа бүртгэх,

So that барааны мэдээллийг системд хадгалж ашиглах боломжтой болно.

### Acceptance Criteria

- AC-01-01 (Normal): Шинэ SKU болон шаардлагатай мэдээлэл өгвөл бараа бүртгэгдэнэ.
- AC-01-02 (Error): Давхардсан SKU оруулбал шинэ бараа үүсэхгүй.
- AC-01-03 (Error): Шаардлагатай мэдээлэл дутуу бол бүртгэл хийгдэхгүй.

## US-02 — Орлого бүртгэх

As an агуулахын ажилтан,

I want to барааны орлого бүртгэх,

So that агуулахын үлдэгдэл нэмэгдэнэ.

### Acceptance Criteria

- AC-02-01 (Normal): Тоо хэмжээ 0-ээс их бол үлдэгдэл нэмэгдэнэ.
- AC-02-02 (Boundary): Тоо хэмжээ 0 бол орлого бүртгэгдэхгүй, үлдэгдэл өөрчлөгдөхгүй.
- AC-02-03 (Error): Сөрөг тоо хэмжээ оруулбал бүртгэл хийгдэхгүй, үлдэгдэл өөрчлөгдөхгүй.

## US-03 — Зарлага бүртгэх

As an агуулахын ажилтан,

I want to барааны зарлага бүртгэх,

So that агуулахын үлдэгдэл зөв буурна.

### Acceptance Criteria

- AC-03-01 (Normal): Зарлагын тоо үлдэгдлээс бага бол үлдэгдэл буурна.
- AC-03-02 (Boundary): Зарлагын тоо үлдэгдэлтэй тэнцүү бол үлдэгдэл 0 болно.
- AC-03-03 (Error): Зарлагын тоо үлдэгдлээс их бол зарлага бүртгэгдэхгүй, үлдэгдэл өөрчлөгдөхгүй.

## US-04 — Үлдэгдэл шалгах

As a менежер,

I want to бараа бүрийн үлдэгдлийг харах,

So that агуулахын одоогийн нөөцийг мэдэх боломжтой болно.

### Acceptance Criteria

- AC-04-01 (Normal): Эерэг үлдэгдэлтэй барааны бодит тоо харагдана.
- AC-04-02 (Boundary): Үлдэгдэл 0 бол 0 гэж харагдана.
- AC-04-03 (Error): Бүртгэлгүй SKU хайвал бараа олдсонгүй гэсэн мэдээлэл гарна.

## US-05 — Бага үлдэгдэл илрүүлэх

As a менежер,

I want to бага үлдэгдэлтэй барааг харах,

So that дуусах гэж байгаа барааг урьдчилан мэднэ.

### Acceptance Criteria

- AC-05-01 (Normal): Үлдэгдэл 5-аас бага бол жагсаалтад орно.
- AC-05-02 (Boundary): Үлдэгдэл яг 5 бол бага үлдэгдэлд орохгүй.
- AC-05-03 (Normal): Үлдэгдэл 5-аас их бол бага үлдэгдлийн жагсаалтад орохгүй.

## US-06 — Хөдөлгөөний түүх харах

As a менежер,

I want to барааны орлого, зарлагын түүхийг харах,

So that өмнөх хөдөлгөөнүүдийг шалгах боломжтой болно.

### Acceptance Criteria

- AC-06-01 (Normal): Бүртгэгдсэн орлого, зарлага түүхэнд харагдана.
- AC-06-02 (Boundary): Хөдөлгөөн байхгүй бол хоосон түүхийн мэдээлэл харагдана.
- AC-06-03 (Error): Татгалзсан зарлага амжилттай хөдөлгөөн мэт бүртгэгдэхгүй.

## US-07 — Баримт шалгах

As an агуулахын ажилтан,

I want to орлого болон зарлагын баримтыг шалгах,

So that буруу мэдээлэл хадгалагдахаас сэргийлнэ.

### Acceptance Criteria

- AC-07-01 (Normal): Шаардлагатай мэдээлэл бүрэн бол баримтыг хүлээн авна.
- AC-07-02 (Error): Шаардлагатай талбар дутуу бол баримт хадгалагдахгүй.
- AC-07-03 (Error): Баримтын мэдээлэл зөрүүтэй бол баталгаажуулахгүй.

## US-08 — Нөөц хүрэлцэхгүй үед хамгаалах

As a систем,

I want to үлдэгдэл хүрэлцэхгүй үед зарлагыг хориглох,

So that сөрөг үлдэгдэл үүсэхээс хамгаална.

### Acceptance Criteria

- AC-08-01 (Normal): Нөөц хүрэлцвэл зарлага амжилттай бүртгэгдэнэ.
- AC-08-02 (Error): Нөөц хүрэлцэхгүй бол зарлага татгалзагдаж, өмнөх үлдэгдэл өөрчлөгдөхгүй.
- AC-08-03 (Boundary): Зарлагын тоо үлдэгдэлтэй тэнцүү бол зарлага зөвшөөрөгдөж, үлдэгдэл 0 болно.

## Бизнесийн дүрэм

1. Давхардсан SKU бүртгэхгүй.
2. Тоо хэмжээ 0 бол хөдөлгөөн бүртгэхгүй.
3. Сөрөг тоо хэмжээ бүртгэхгүй.
4. Үлдэгдэл хүрэлцэхгүй бол зарлага хийхгүй.
5. Татгалзсан үйлдэл үлдэгдлийг өөрчлөхгүй.
6. Бага үлдэгдлийн босго 5 байна.
7. Бүх хөдөлгөөн түүхэнд хадгалагдана.

## Дүгнэлт

Энэ лабораторийн ажлаар агуулахын системийн 8 User Story болон тус бүрийн 3 Acceptance Criteria тодорхойлсон.

Мөн хэвийн, хил заагийн болон алдаатай нөхцөлүүдийг тусгасан.

Дараагийн шатанд эдгээр шаардлагыг өгөгдлийн сан болон API-тай холбоно.

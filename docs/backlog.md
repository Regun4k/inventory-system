# Project Backlog – Warehouse Management System

## Төслийн зорилго

Агуулахын барааны бүртгэл, орлого, зарлага, үлдэгдэл болон хайлтын үйл ажиллагааг зохион байгуулах.

## Milestones — одоогийн функцийн backlog

### M1 – Барааны бүртгэл
**Зорилго:** Барааны үндсэн мэдээллийг бүртгэх.

Хийх ажил:
- SKU тодорхойлох
- Барааны нэр бүртгэх
- Барааны мэдээлэл хадгалах
- Давхардсан SKU шалгах

**Дууссан гэж үзэх нөхцөл:** Шинэ бараа бүртгэж, давхардлыг шалгах боломжтой болсон байх.

### M2 – Барааны орлого
**Зорилго:** Агуулахад ирсэн барааг баримтаар бүртгэх.

Хийх ажил:
- Орлогын баримт DRAFT хадгалах
- SKU, огноо, тоо хэмжээ шалгах
- Баримтыг батлах (POSTED)
- Давхар батлалтыг хориглох

**Дууссан гэж үзэх нөхцөл:** DRAFT үлдэгдэлд нөлөөлөхгүй, POSTED нэг удаа үлдэгдэлд нөлөөлдөг байх.

### M3 – Барааны зарлага
**Зорилго:** Агуулахаас гарсан барааг бүртгэх.

Хийх ажил:
- Зарлагын баримт DRAFT үүсгэх
- Батлах үед үлдэгдэл шалгах
- Хүрэлцэхгүй үлдэгдлийг татгалзах
- Батлагдсан зарлагыг хөдөлгөөний түүхэнд хадгалах

**Дууссан гэж үзэх нөхцөл:** Зөвхөн батлагдсан зарлага үлдэгдлийг бууруулдаг, сөрөг үлдэгдэл үүсгэдэггүй байх.

### M4 – Үлдэгдэл шалгах
**Зорилго:** Барааны үлдэгдлийг агуулах тус бүрээр харах.

Хийх ажил:
- Агуулахын жагсаалт гаргах
- SKU-г агуулах тус бүрээр шүүх
- Агуулах тус бүрийн үлдэгдэл харуулах
- Нийт үлдэгдлийг нэгтгэх
- Бараа бүртгэлтэй боловч тухайн агуулахад хөдөлгөөнгүй бол 0 харуулах

**Дууссан гэж үзэх нөхцөл:** Агуулах тус бүрийн үлдэгдэл болон нийлбэр зөв харагдах.

### M5 – Бага үлдэгдэл шалгах
**Зорилго:** Сонгосон агуулах дахь бага үлдэгдэлтэй барааг илрүүлэх.

Хийх ажил:
- Үлдэгдлийн босго тодорхойлох
- 5-аас бага үлдэгдэлтэй барааг шүүх
- Агуулахын нэр болон барааны мэдээлэл харуулах

**Дууссан гэж үзэх нөхцөл:** Босгыг агуулах тус бүрээр зөв шалгадаг байх.

### M6 – Баримт, батлалт ба буцаалт
**Зорилго:** Баримтын төлөв болон залруулгыг хянах.

Хийх ажил:
- Баримтын дугаар, огноо, мөр шалгах
- DRAFT / POSTED / REVERSED төлөв хэрэгжүүлэх
- Нэг баримтыг давхар батлахгүй байх
- POSTED баримтыг шууд засахгүй байх
- Буцаалт/reversal-ийг эх баримттай холбож бүртгэх

**Дууссан гэж үзэх нөхцөл:** Төлөвийн дүрэм мөрдөгдөж, хөдөлгөөн давхардахгүй, буцаалт түүхэнд тусдаа харагдах.

### M7 – Бараа хайх
**Зорилго:** Барааг хурдан хайж олох.

Хийх ажил:
- SKU-аар хайх
- Барааны нэрээр хайх
- Агуулахын үлдэгдэлтэй хамт үр дүн харуулах
- Олдоогүй мэдээлэл харуулах

**Дууссан гэж үзэх нөхцөл:** SKU болон нэрээр хайлт хийж, бүртгэлгүй SKU-г ялгадаг байх.

### M8 – Тест ба шалгалт
**Зорилго:** Системийн шаардлагуудыг шалгах.

Хийх ажил:
- 24 Acceptance Criteria-г шалгах
- DRAFT, POSTED, давхар батлалт, reversal шалгах
- Хоёр агуулахын 0 болон нийлбэрийн тооцоолол шалгах
- Хэрэглэгчийн эрх болон аудитын мөр шалгах
- Баримт бичгийг хянах

**Дууссан гэж үзэх нөхцөл:** Шалгалтын оролт, хүлээгдэж буй үр дүн, бодит үр дүнг тэмдэглэсэн байх.

## Сургалтын G1–G8 үе шаттай холбосон зураглал

Доорх нь одоогийн функцийн backlog-ийг G1–G8 сургалтын дараалалтай холбосон төслийн ажлын зураглал юм. Албан ёсны хичээлийн G1–G8 нэршил өөр байвал багшийн өгсөн нэршлээр тааруулна.

| Сургалтын үе | Төслийн зорилго, хийх ажил | Холбогдох backlog |
|---|---|---|
| G1 | Асуудал, хэрэглэгч, 8 User Story, 24 AC, эрсдэл, GitHub workflow, G1 review | Одоогийн L01–L08, M1–M8-ийн шаардлагын суурь |
| G2 | Өгөгдлийн загвар: бараа, агуулах, үлдэгдэл, баримт, баримтын мөр, хэрэглэгч, аудитын entity ба холбоос | L09; M1, M4, M6 |
| G3 | Төлөвийн дүрэм: DRAFT, POSTED, REVERSED; validation; нэг удаагийн батлалт; POSTED баримтын өөрчлөлтийн хориг | L10; M2, M3, M6 |
| G4 | API гэрээ: endpoint, request/response, validation error, conflict болон зөвшөөрлийн хариу | L11; M1–M7 |
| G5 | Орлого, зарлага, батлалт ба reversal-ийг хэрэгжүүлэх | M2, M3, M6 |
| G6 | Олон агуулах: үлдэгдлийг агуулах тус бүрээр хадгалах, 0 үлдэгдлийг ялгах, нийт дүн нэгтгэх | M4, M5 |
| G7 | Хэрэглэгчийн эрх ба аудит: агуулахын ажилтан, менежер, админ; хэн ямар үйлдэл хийснийг бүртгэх | M1–M8-ийн эрх/аудитын өргөтгөл |
| G8 | Нэгдсэн шалгалт, хүлээн авах шалгуурын бодит үр дүн, баримт бичиг ба хүлээлгэн өгөх | M8 |

## Дараагийн ажлын дараалал

1. **L09 — Өгөгдлийн загвар:** бараа, агуулах, үлдэгдэл, баримт, хэрэглэгч, аудитын хүснэгт болон холбоос.
2. **L10 — Төлвийн дүрэм:** DRAFT → POSTED → REVERSED шилжилт, үлдэгдэлд нөлөөлөх нөхцөл, давхар батлалтаас хамгаалах.
3. **L11 — API гэрээ:** орлого/зарлага хадгалах, батлах, буцаах, үлдэгдэл харах API-ийн оролт/гаралт ба алдааны нөхцөл.
4. Дараа нь G5–G8 шатны хэрэгжүүлэлт, эрх/аудит, нэгдсэн шалгалтыг хийх.

## Тайлбар

Milestone бүрийн төлөвийг бодит гүйцэтгэлээс хамаарч шинэчилнэ. Баримт бичигт төлөвлөсөн ажил нь системд бүрэн хэрэгжсэн гэсэн үг биш.


### G7 — эрх ба аудитын ажлын хүрээ

**Үүргийн матрицын санал:**
- Агуулахын ажилтан: бараа болон үлдэгдэл харах, орлого/зарлагын DRAFT үүсгэх; POSTED баримтыг шууд өөрчлөх эрхгүй.
- Менежер: DRAFT баримтыг шалгах, зөвшөөрч POSTED болгох; reversal хүсэлтийг шалгах.
- Админ: хэрэглэгч, үүрэг, барааны лавлах болон агуулахын үндсэн мэдээллийг удирдах.

**Аудитын мөрөнд хадгалах мэдээлэл:**
- Үйлдэл хийсэн хэрэглэгчийн ID;
- Үйлдлийн огноо, цаг;
- Үйлдлийн төрөл (CREATE_DRAFT, POST, REVERSE гэх мэт);
- Баримтын дугаар ба төлөвийн өмнөх/дараах утга;
- Агуулах, SKU, тоо хэмжээ;
- Reversal хийсэн бол эх баримтын дугаар болон тайлбар.

Энэ нь G7 шатанд баталгаажуулах төлөвлөгөө бөгөөд эрхийн эцсийн матриц, audit schema-г хэрэгжүүлэхээс өмнө L09–L11-ийн загвар болон API гэрээтэй уялдуулна.

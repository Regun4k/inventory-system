## 4. Шаардлагын тодорхойгүй нөхцөлүүд

Өөрийн баримтыг дахин шалгахад дараах хоёр зүйлийг тодруулах шаардлагатай гэж үзсэн.

### 4.1 SKU-ийн том, жижиг үсэг

Жишээ нь `A001` болон `a001` кодыг ижил бараа гэж үзэх эсэхийг дараагийн шатанд шийднэ.

### 4.2 Бага үлдэгдлийн босго

Одоогийн шаардлагад 5 гэж тогтоосон.

Цаашид хэрэглэгч өөрөө босгыг өөрчилж болох эсэхийг тодруулах шаардлагатай.

## 5. Peer Review

Хөрш оюутан эсвэл багийн хүнээр дараах зүйлсийг шалгуулна.

- 8 User Story байгаа эсэх.
- Story бүр 3 Acceptance Criteria-тай эсэх.
- 0 болон сөрөг тоо орсон эсэх.
- Давхардсан SKU болон нөөц хүрэлцэхгүй нөхцөл орсон эсэх.

### Review бүртгэл

| Хэсэг | Мэдээлэл |
|---|---|
| Шалгасан хүн | Бодит reviewer-ийн нэрийг бөглөх |
| Огноо | Review хийсэн огноо |
| Санал | Review-ийн бодит саналыг бичих |
| Миний шийдвэр | Саналыг зөвшөөрсөн эсвэл няцаасан шалтгаан |
| Засвар | Хийсэн өөрчлөлт |

Одоогоор бодит peer review хийгдээгүй тул энэ хэсгийг баталгаажуулах шаардлагатай.

## 6. Нөхөн хийх ажил

1. `traceability.md` файлыг docs хавтаст байрлуулах.
2. Peer review авах.
3. SQL JOIN-ийг MySQL дээр ажиллуулж шалгах.
4. Story бүрийн тестийг дараагийн хөгжүүлэлтийн шатанд хэрэгжүүлэх.

## 7. Дүгнэлт

Энэ лабораторийн ажлаар 8 User Story болон 24 Acceptance Criteria-г хооронд нь холбосон.

Мөн шаардлагуудыг шалгах 24 тестийн дугаар тодорхойлсон.

Дараагийн шатанд эдгээр шаардлагыг бодит өгөгдлийн сан болон системийн тесттэй холбож ажиллана.
